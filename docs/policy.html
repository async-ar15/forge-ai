Policy Engine

Contextual Bandit Routing with LinUCB

The Brain of ForgeAI

The Policy Engine uses a Reinforcement Learning algorithm called LinUCB (Linear Upper Confidence Bound). Instead of hardcoding rules, the system learns over time which combination of settings yields the best latency and cost for a given type of request.

State Vector (Pre-Execution Features)

Before any model is invoked, the gateway extracts an 8-dimensional state vector from the incoming request in under 5ms:

  • query_len: Token count of the input prompt.
  • token_budget: The requested max output tokens.
  • query_type: RAG, Code, Chat, Summarize, or Unknown.
  • tenant_tier: Free, Pro, Enterprise, or Internal.
  • latency_slo_ms: The Service Level Objective for latency.
  • queue_depth: Current load on the execution queue.
  • gpu_load: Live GPU utilization metrics.
  • cache_hit_prob: Probability of a semantic cache hit (queried via Redis Bloom).

The 81 Joint Actions

Based on the state vector, the bandit chooses one of 81 possible joint actions. An action is a combination of four discrete variables:

graph LR A[Model Tier] -->|Small, Medium, Large| B[Precision] B -->|FP16, INT8, INT4| C[Retrieval Mode] C -->|Off, Cache-Only, Full| D[Output Budget] D -->|Short, Medium, Long| E((Action Selected))

Every decision is logged to Kafka with an exploration flag. The online reward is computed synchronously before returning the response to the user, and the policy is retrained on exploitative history offline.
